### [bug] Timer auto-finish uses a stale finishENT closure, losing all answers/time on timeout
`FullENT.tsx:133-139` · confidence 0.9

**Issue:** The interval effect calls finishENT() when the clock hits 0, but its dependency array is [phase, paused, offline]. finishENT is recreated on every render and closes over `answers`, `timeLeft`, and `qTimesRef`. The interval is only re-created when phase/paused/offline change — NOT when `answers` changes. So the finishENT captured inside the running interval is the one from the render when the test first started (or last pause/offline toggle), where `answers` is still empty. If the 4-hour timer actually expires (or in tests/fast-forward), calcResults() runs against a stale `answers` snapshot, scoring the student 0 / losing their work. The manual finish paths (nxt/finishEarly) are fine because they call the fresh finishENT directly; only the timer path is poisoned.

**Fix:** Make the interval call the latest finishENT rather than a captured stale one. Minimal ref approach: declare `const finishRef = useRef(finishENT); finishRef.current = finishENT;` (placed after finishENT is defined, or assign in a useEffect with no deps that runs every render), then change line 137 to call `finishRef.current()` instead of `finishENT()`. Alternatively, in the interval updater just `return 0` on expiry and add a dedicated effect: `useEffect(() => { if (phase === 'test' && timeLeft === 0) finishENT(); }, [timeLeft, phase]);` — this effect re-runs with fresh `answers`/`timeLeft` in scope. Either way verify the existing guards in finishENT (clearInterval, flushQTime, setPhase('results')) still run exactly once. Add a test that fast-forwards the timer to 0 after recording answers and asserts the scored result reflects those answers, not an empty set.

### [a11y] Modal dialog has no focus trap and does not restore focus on close
`ui/BottomSheet.tsx:24` · confidence 0.9

**Issue:** The sheet sets role=dialog/aria-modal and focuses itself on open and handles Escape, but there is no focus trap: Tab moves focus out of the dialog to background content behind the overlay. It also never restores focus to the element that opened the sheet when it closes. Both are required focus-management behaviors for an accessible modal.

**Fix:** In the open effect, capture the trigger and restore on cleanup, and add a Tab trap. Replace the effect body with: store `const prev = document.activeElement as HTMLElement | null;` then on cleanup call `prev?.focus()`. For the trap, in handleKey also handle Tab: query focusable elements within sheetRef (e.g. `sheetRef.current.querySelectorAll('button, [href], input, select, textarea, [tabindex]:not([tabindex="-1"])')`), and when Tab/Shift+Tab would move past the first/last, preventDefault and wrap focus to the other end. Minimal version:

useEffect(() => {
  if (!visible) return;
  const prev = document.activeElement as HTMLElement | null;
  const handleKey = (e: KeyboardEvent) => {
    if (e.key === 'Escape') { onClose(); return; }
    if (e.key !== 'Tab' || !sheetRef.current) return;
    const f = sheetRef.current.querySelectorAll<HTMLElement>('a[href],button:not([disabled]),input:not([disabled]),select:not([disabled]),textarea:not([disabled]),[tabindex]:not([tabindex="-1"])');
    if (!f.length) { e.preventDefault(); sheetRef.current.focus(); return; }
    const first = f[0], last = f[f.length - 1];
    if (e.shiftKey && document.activeElement === first) { e.preventDefault(); last.focus(); }
    else if (!e.shiftKey && document.activeElement === last) { e.preventDefault(); first.focus(); }
  };
  document.addEventListener('keydown', handleKey);
  sheetRef.current?.focus();
  return () => { document.removeEventListener('keydown', handleKey); prev?.focus(); };
}, [visible, onClose]);

Preferred alternative per project "no wheel inventions" rule: wrap children in focus-trap-react (or migrate to @radix-ui/react-dialog) instead of the hand-rolled trap, since it also handles edge cases (initial focus, nested portals, sentinel nodes).
